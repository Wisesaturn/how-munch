# create-github-issue

계획·스펙을 **grill**(미해소 결정을 한 문항씩 해소)로 명확히 한 뒤, **vertical slice** 단위 이슈로 쪼개 **발행 전 요약**으로 승인받고 발행한다. 작업이 크면 부모 이슈 + **sub-issue**로 구조화한다.

제목 규칙·유형별 템플릿·gh 명령은 전부 `rules/GUIDE.md`에 있다(상단 목차로 섹션 이동). 필요한 섹션만 골라 읽고, 여기 본문에 다시 옮겨 적지 않는다.

---

## 1단계: 맥락 수집

대화 맥락과 인자를 먼저 읽는다.

- 인자가 이슈 번호·URL·파일 경로면 `gh issue view`로 본문·댓글을 가져와 읽는다.
- 코드베이스를 탐색해 "무엇을, 어디에" 만들지 후보를 잡는다. 제목·본문은 코드 실제 용어를 따른다.

> **완료 기준**: 무엇을 만들지 / 어느 도메인·대상 영역인지 후보를 말할 수 있다.

## 2단계: Grill

아직 안 정해진 결정만 **한 문항씩** 묻는다. 각 질문에는 **추천답**을 함께 제시한다.

- 코드베이스 탐색으로 답할 수 있는 질문이면 → 묻지 말고 탐색해서 자답한다.
- 대화 맥락에 이미 답이 있으면 → 건너뛴다.

해소해야 할 분기:

- **유형**: Feature / Fix / Bug / Refactor / Chore 중 무엇인가 (구분 기준은 `rules/GUIDE.md` → "이슈 제목 규칙" 섹션)
- **도메인/대상 영역**: 어떤 화면·도메인에서 구현·수정하는가
- **범위**: 단일 이슈인가, 여러 vertical slice로 쪼개야 하는가

> **완료 기준**: 위 분기가 모두 해소되어 이슈 제목 후보를 적을 수 있다.

## 3단계: Vertical slice 초안

작업이 한 이슈로 안 끝나면 **tracer bullet**으로 쪼갠다.

- 각 슬라이스는 한 레이어(예: API만)가 아니라 끝에서 끝까지 관통하는 **얇고 완결된 경로**다 — 그 자체로 검증·시연 가능해야 한다.
- 두꺼운 슬라이스 몇 개보다 얇은 슬라이스 여러 개를 선호한다.
- 하위 기능으로 더 쪼개지는 큰 작업이면 **부모 이슈 1개 + sub-issue N개** 구조로 잡는다.
- 슬라이스 간 의존관계(blocked-by)를 정한다.

> **완료 기준**: 슬라이스 목록과 의존순서, 부모/sub-issue 관계가 확정됐다.

## 4단계: 발행 전 요약 (승인 게이트)

발행 **전에** 만들 이슈를 번호 리스트로 제시하고 승인받는다. 각 항목에 표기:

- **제목** (`rules/GUIDE.md` → "이슈 제목 규칙" 섹션 준수)
- **유형 / 도메인·대상 영역**
- **부모 관계**: 부모 이슈 / sub-issue 여부
- **Blocked by**: 선행 슬라이스 (없으면 "없음")

사용자에게 묻는다: 분할 단위가 적절한가? 의존관계가 맞는가? 합치거나 더 쪼갤 슬라이스가 있는가?

> **완료 기준**: 사용자가 목록을 명시적으로 승인했다. 승인 전에는 절대 발행하지 않는다.

## 5단계: 발행

승인된 슬라이스를 **의존순서대로(부모·blocker 먼저)** 발행한다.

- 유형별 템플릿을 `rules/GUIDE.md`의 **해당 유형 섹션만** 가져와 채운다(예: Feature면 "기능 구현 템플릿"). 유형별 레이블(`feature`/`fix`/`bug`/`refactor`/`chore`)을 `--label`로 지정한다.
- sub-issue는 부모·자식을 모두 생성한 뒤 `rules/GUIDE.md` → "gh CLI 명령어 패턴"의 sub-issue 연결 명령으로 부모에 붙인다.
- blocked-by가 있으면 본문에 실제 이슈 번호로 참조한다(그래서 부모·blocker를 먼저 발행).
- 인자로 받은 부모 이슈는 **닫거나 수정하지 않는다**.

> **완료 기준**: 생성된 모든 이슈의 번호·URL과 sub-issue 연결 결과를 출력했다.

---

## 주의사항

- `gh` CLI가 설치되어 있어야 합니다: `brew install gh`
- 인증이 필요합니다: `gh auth login`
- 레이블은 레포에 미리 생성되어 있어야 합니다
